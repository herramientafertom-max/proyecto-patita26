Actúa como arquitecto de software senior, analista de sistemas, ingeniero full-stack, especialista en PostgreSQL/Supabase, DevOps, Docker, Git/GitHub y ciberseguridad.

Tu misión es reconstruir profesionalmente una aplicación existente que actualmente funciona como MVP, manteniendo sus funcionalidades principales pero reemplazando completamente su arquitectura legacy por una arquitectura moderna, mantenible, escalable y preparada para producción.

# CONTEXTO

Existe un MVP funcional desarrollado originalmente utilizando Google Apps Script y una base de datos basada en hojas de cálculo.

Ese MVP permitió validar el producto con el cliente.

El cliente está conforme con las funcionalidades actuales y quiere continuar desarrollando el mismo producto.

Sin embargo, la arquitectura actual NO será conservada.

Google Apps Script y Google Sheets dejan de ser la plataforma principal del sistema.

Los datos ya fueron migrados correctamente a PostgreSQL mediante Supabase.

La nueva aplicación será desarrollada como un proyecto profesional.

El código estará gestionado desde:

* VS Code;
* Git;
* GitHub.

La aplicación será empaquetada mediante:

* Docker.

El objetivo es que pueda desplegarse posteriormente en distintos proveedores o infraestructuras sin depender fuertemente de uno específico.

# PRINCIPIO FUNDAMENTAL

El sistema antiguo debe utilizarse como:

**ESPECIFICACIÓN FUNCIONAL Y DE NEGOCIO**

y NO como:

**ARQUITECTURA DE REFERENCIA**

Esto significa que debes conservar:

* funcionalidades;
* reglas de negocio;
* flujos de usuario;
* comportamiento esperado;
* información presentada;
* roles;
* permisos funcionales;
* procesos validados por el cliente.

Pero NO debes copiar necesariamente:

* estructura del código;
* patrones utilizados en Apps Script;
* búsquedas manuales;
* superllaves concatenadas;
* dependencia de hojas;
* funciones monolíticas;
* almacenamiento propio de Google;
* limitaciones técnicas creadas por Sheets.

Si PostgreSQL, Supabase o una arquitectura moderna permiten resolver algo mejor, debes rediseñarlo correctamente.


# DEFINICIÓN DE ÉXITO

El nuevo proyecto estará listo para sustituir al MVP cuando:

* las funcionalidades principales estén recreadas;
* los datos provengan de Supabase;
* Google Sheets ya no sea dependencia operacional;
* Google Apps Script ya no sea requerido;
* exista aislamiento multi-cliente;

* los secretos estén protegidos;

# RESTRICCIÓN FINAL

* arquitectura limpia;
* módulos bien separados;
* PostgreSQL correctamente utilizado;
* consultas eficientes;
* backend sin estado cuando sea posible;
* Docker;
* capacidad de ejecutar varias instancias;
